# ApiHarvesters

Пайплайн подготовки документов, опубликованных в России, для извлечения формул:
сбор метаданных и ссылок из первичных источников → поиск и скачивание PDF →
временное хранилище уникальных PDF (по SHA-256) для этапа извлечения формул.

## Источники

Российскими считаются документы, опубликованные в России (российский журнал или
репозиторий). Источники выбраны по заявленным входам агрегаторов: берутся первичные
источники, а не производные агрегаторы (OpenAlex, Unpaywall и т. п. собирают те же данные).

| Источник | Доступ | Что даёт |
|---|---|---|
| Crossref | REST API | статьи всех российских издателей - участников Crossref (около 1700 организаций, отбираются по полю `location` реестра участников; список кешируется на 30 дней) |
| DOAJ | REST API | статьи российских журналов открытого доступа: статьи без DOI и прямые ссылки на полный текст от журналов |
| OAI-PMH | OAI-PMH | репозитории российских университетов: диссертации, выпускные работы, препринты (список - `code`). Сбор инкрементальный: первый обход - весь каталог, далее - изменения с прошлого успешного обхода (таблица `harvest_state`); год публикации не используется |

Почему не используются агрегаторы:
- OpenAlex собирает Crossref, DOAJ, репозитории и др., но PDF российских сайтов находит
  плохо (сбор идёт с американского адреса с таймаутом 15 с);
- КиберЛенинка: robots.txt запрещает роботам загрузку PDF;
- Semantic Scholar, zbMATH, Unpaywall - производные или не хранят PDF.

## Хранение (PostgreSQL)

| Таблица | Строка - это | Ключ |
|---|---|---|
| `works` | научная работа; копии из разных источников объединяются по DOI | `id`, уникальный `doi` |
| `work_sources` | где найдена работа: копия в источнике, ссылка на PDF и/или страницу, статус проверки | MD5(`source:external_id`) |
| `pdf_files` | уникальный PDF-файл (документ), передаваемый на извлечение формул | SHA-256 содержимого |
| `formulas` | уникальная формула: каноническое дерево разбора, LaTeX для показа, `df` | MD5 дерева |
| `formula_occurrences` | вхождение формулы в документ: страница, `tf` (число вхождений на странице) | формула + `pdf_sha256` + страница |

```
works 1 ── N work_sources N ── 1 pdf_files 1 ── N formula_occurrences N ── 1 formulas
      1 ──────────────── N pdf_files
```

Одна работа может быть найдена в нескольких источниках (например, статья с DOI - в Crossref
и DOAJ): название и DOI хранятся один раз в `works`, а в `work_sources` - только то, что
зависит от источника. Разные PDF одной работы (например, препринт и опубликованная версия) -
разные документы: из них могут извлекаться разные формулы. Одинаковые файлы, полученные
разными путями, дают один документ.

Изменения схемы существующей БД - в каталоге `docker/database/migrations` (SQL, применяются вручную).

## Этапы

```bash
# 1. сбор метаданных и ссылок (быстро: страницы статей не открываются)
python run.py harvest --year 2024
python run.py harvest --works_sources doaj oai --year 2024 --limit 100
python run.py harvest --works_sources oai --oai-per-repo 20   # тест: по 20 записей из каждого репозитория

# 2. загрузка PDF: прямые ссылки, иначе мета-тег citation_pdf_url на странице статьи;
#    проверка сигнатуры %PDF, SHA-256, файл - в pdf_storage/<sha[:2]>/<sha>.pdf
python run.py download --limit 300

# 3. извлечение формул (MinerU), разбор, запись в индекс;
#    PDF после обработки удаляется только в продакшн-версии (APP_ENV=production)
python run.py extract --limit 10
python run.py extract --tier standard               # модели с VLM

# 4. сводка
python run.py stats
```

## Извлечение формул и индекс

1. **Распознавание** - MinerU (модели `basic`: формулы, текст, таблицы на CPU; `standard`
   дополнительно использует VLM). MinerU работает в отдельном окружении
   (`~/.mineru/venv` или переменная `MINERU_PYTHON`) и запускается подпроцессом
   (`code`). Результат - формулы LaTeX с номерами страниц:
   выносные (`equation`) и строчные (`equation_inline`).
2. **Разбор** (`code`) - LaTeX разбирается библиотекой `pylatexenc`,
   затем разбором с приоритетами операций строится дерево вида
   `{"=": [{"+": ["a", "b"]}, "c"]}`. Разбор не прерывается на нераспознанных фрагментах
   (их число - `ParsedFormula.skipped`); формула делится на части по `,`, `;`, `&`, `\\`.
   Учитываются особенности вывода MinerU: поцифренная запись чисел (`1 0` → 10),
   десятичная запятая (`0 , 26` → 0.26), `\operatorname*{m a x}` → `\max`.
3. **Индекс** - дерево подстановок `data/index_data`
   (`code`): формула - путь из символов дерева разбора в порядке
   обхода в ширину. Для коммутативных операций добавляются варианты с переставленными
   операндами (не больше 64 на формулу). Формат совместим с нечётким поиском
   веб-приложения; запрос строится функцией `latex_to_query(latex)` тем же разборщиком.

Время на CPU: `basic` - от 5 до 30 с на страницу; `standard` - в несколько раз дольше.

## Маршрутизация

`RoutedSession` выбирает маршрут по домену: сайты в зонах `.ru`, `.su`, `.рф` открываются
напрямую, остальные - через системный прокси (если он настроен). Маршрут пересчитывается
на каждом редиректе (например, `doi.org` → сайт журнала). Список прямых доменов задаётся
переменной `DIRECT_HOSTS` (регулярное выражение).

## Запуск

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
docker compose up -d postgres          # БД на localhost:5433 (python/python, formula_index)
.venv\Scripts\python run.py harvest --year 2024 --limit 100
.venv\Scripts\python run.py download
```

В Docker сбор и загрузка запускаются по расписанию (`docker/crontab`), PDF хранятся
в каталоге `pdf_storage` проекта (смонтирован в контейнер как `/data/pdf`; пути файлов
в БД - относительно хранилища). Извлечение формул пока запускается на хосте. Контейнеру нужен прямой доступ к российским сайтам: если на
компьютере работает прокси с перехватом всего трафика, российские домены нужно
направить в обход прокси.

Переменные окружения: `DATABASE_URL`, `DIRECT_HOSTS`, `CROSSREF_MEMBERS_CACHE`, `MINERU_PYTHON`,
`APP_ENV` (`production` - удалять PDF после извлечения формул; по умолчанию `development`).

## Резервные копии

Тома Docker (в том числе том БД) хранятся внутри Docker и пропадают при его удалении
или переустановке. Сервис `backup` выгружает БД (`pg_dump`, формат custom) в каталог
`docker/database/backups` проекта и хранит 14 последних копий (`BACKUP_KEEP`). Он запускается только
вручную - одна копия за запуск:

```bash
docker compose run --rm backup
```

Копирование по расписанию отключено; его можно включить, задав период в секундах
(`BACKUP_INTERVAL=86400`) и запустив сервис в фоне. Дерево индекса (`data/index_data`) и PDF
(`data/pdf_storage`) и так хранятся в каталоге проекта.

Восстановление из копии (в работающий контейнер Postgres, существующие таблицы заменяются):

```bash
docker compose up -d postgres
docker exec -i api_harvesters_postgres pg_restore -U python -d formula_index --clean --if-exists < backups/formula_index_2026-11-01_2318.dump
```

## Известные ограничения

- Часть OAI-интерфейсов не отдаёт записи (СПбГУ, ЮУрГУ, НГУ, УрГЛТУ, библиотека
  им. Белинского) или отдаёт неработающие ссылки (Самарский университет) -
  закомментированы в списке.
- Сайты с недействительным сертификатом (например, с истёкшим) пропускаются:
  проверка сертификатов не отключается.
